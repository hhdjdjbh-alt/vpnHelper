# vpnHelper

Установка AmneziaWG или VLESS + TCP + Reality на VPS через SSH. Скрипт спрашивает параметры сервера и имя клиента, выводит готовый профиль и сохраняет его в выбранную папку.

## Требования

На компьютере: macOS или Linux, Python 3.9+ и OpenSSH. Python-библиотеки устанавливать не нужно.

На VPS: Debian или Ubuntu с systemd, доступ root по SSH и выход в интернет. Для AmneziaWG нужен `/dev/net/tun`. Автоматическая сборка и установка рассчитаны на x86_64 и arm64.

## Запуск

Скачайте репозиторий целиком, откройте терминал в его папке и выполните:

```sh
python3 vpn_setup.py
```

Выберите протокол:

- **AmneziaWG** — клиентский `.conf`, по умолчанию UDP 51820. Используются классические параметры AWG, без возможностей AWG 2/3.
- **VLESS + TCP + Reality** — ссылка `vless://` в `.txt`, flow `xtls-rprx-vision`, по умолчанию TCP 443. Подходит для клиента с поддержкой Reality, например Happ. Свой домен и сертификат для VPS не нужны.

Далее укажите адрес VPS, SSH-порт, порт VPN, имя клиента, способ входа по SSH и папку для конфигурации. Для Reality дополнительно нужен домен маскировки с TLS 1.3 и HTTP/2; скрипт проверяет его доступность с VPS.

Пароль запрашивает SSH. Скрипт его не сохраняет. Профиль по умолчанию попадает в `configs/` с правами 600. Существующие файлы не перезаписываются. В панели хостинга разрешите входящий порт, который показан в конце установки.

Все файлы проекта должны оставаться вместе. Shell-сценарии запускаются установщиком на VPS, вручную запускать их на компьютере не нужно.

## Проверка конфигов без сервера

Интерактивная проверка файла или папки:

```sh
python3 vpn_setup.py --check
```

Проверка папки с сохранением отчёта:

```sh
python3 vpn_setup.py --check configs --report reports/check.txt
python3 vpn_setup.py --check configs --report reports/check.json
```

Проверяются адреса, порты, формат ключей, UUID, параметры Reality, параметры классического AWG, дубликаты и структура файла. Отчёт показывает несколько ошибок сразу и объясняет, что проверить. Значения полей, ключи и UUID не выводятся; имена файлов остаются в отчёте.

При выборе папки проверяются `.conf` и `.txt` без обхода вложенных папок. Допускается UTF-8 BOM, размер файла — до 256 КиБ. Подписки, JSON, `vpn://`, другие варианты VLESS и расширенные профили AWG не поддерживаются полностью. Исходные файлы не меняются; сеть и SSH не используются. Для каждого нового отчёта выбирайте свободное имя.

Коды завершения: `0` — ошибок формата нет, `1` — ошибки или файл не проверен, `2` — неверные аргументы. Предупреждения возможны и при коде `0`. Успешная офлайн-проверка не подтверждает подключение к серверу.

## Диагностика подключения

AmneziaWG:

```sh
python3 vpn_setup.py --diagnose
```

Показывает службы, UDP-порты, пересылку IPv4, правила NAT/FORWARD и время последнего handshake.

VLESS:

```sh
python3 vpn_setup.py --diagnose-vless
```

Укажите сохранённый `.txt` и SSH-данные. Проверяются TCP-порт, служба Xray, совпадение параметров профиля с серверным файлом, ключ Reality и TLS-соединения с VPS. Конфигурации и службы не меняются.

Если SSH доступен только через другой VPN, диагностику можно запустить с ним. Результат TCP-проверки тогда относится к этому маршруту. Сам по себе открытый порт не подтверждает авторизацию Reality, а недоступный порт не доказывает блокировку IP.

Серверная диагностика рассчитана на установки этого скрипта и стандартный старый конфиг Xray. Сторонние службы и контейнеры Xray автоматически не определяются. При сохранении ошибки нужен журнал клиента без ключей и полной ссылки подключения.

## Повторная установка

VLESS можно добавить на сервер с AmneziaWG или Xray. Установщик использует существующий бинарник Xray и создаёт отдельную службу `vpsvpn-xray-<порт>`. Если TCP-порт занят, выбирается свободный из 443, 8443, 2053, 2083, 2087 и 2096. Фактический порт записывается в профиль.

Каждый повторный запуск VLESS создаёт отдельную службу, а не добавляет клиента в существующую. Новая служба откатывается при ошибке её проверки или запуска. Чужие конфиги и бинарник Xray не заменяются автоматически.

AmneziaWG устанавливается только при отсутствии файлов и интерфейса этой установки. Добавление peers и восстановление частичной установки AWG пока не реализованы.

Копии клиентских профилей на VPS:

- AmneziaWG: `/etc/amnezia/amneziawg/client.conf`.
- VLESS: `/etc/vpsvpn-xray/<порт>/client.txt`.

## Ограничения

Внешний firewall хостинга, сложные правила nftables/UFW, фильтрация сети и маршрутизация в приложении требуют отдельной проверки. У AWG IPv6 направляется в туннель и блокируется; интернет работает по IPv4. У VLESS весь трафик устройства направляет режим VPN/TUN клиента.

При смене SSH-ключа нужно сверить отпечаток через консоль хостинга. Подтверждённый ключ сохраняется в `.ssh-known-hosts` рядом со скриптом; системный `known_hosts` не меняется.

Приложение прошло локальные тесты генерации и проверки конфигов. Полная установка на Linux VPS и подключение из клиентского приложения не проверены в рамках этих тестов. Загрузка Go и Xray проверяется по SHA256; исходники AmneziaWG берутся из текущих upstream-веток.

Конфиги содержат данные доступа. `configs/`, `reports/`, текстовые профили и SSH-данные исключены через `.gitignore`.

## Разработка

```sh
python3 -B -m unittest discover -s tests -v
python3 vpn_setup.py --help
```

Тесты используют временные папки и подставляют внешние команды там, где нужен VPS. Реальные серверы они не настраивают.
